# 移动端 Muse 风格重设计方案

类型：Personal Agent 原生移动端应用，Expo / React Native。

状态：已实现并完成 Android 模拟器主要路径与真实 Controller＋Host 验证；iOS 已通过原生 Debug 构建、真机安装和启动；尚未做完整原生视觉实测。更新：2026-11-26。

## 1. 本次目标与边界

将移动端从紫青渐变调整为 Muse 式的白色、浅灰、轻薄控件与自然留白。底部只保留「聊天」「我的」，定时任务移入「我的」，与设置和插件市场并列。所有已有功能保留，不更改后端、数据协议、权限规则或 Agent 执行机制。

顶栏、导航、选择器、任务、插件和设置按新风格统一；输入框与“+”工具栏按用户后续确认保留原有结构和样式，只做必要的中性底色协调。

助手消息继续没有外层气泡。其内部的内容块顺序、头像与生成状态、文本流式播放、Markdown、工具分组、查看图片、文件交付以及现有动态不在本次重构范围内。只在确有必要时调整外围界面与这些内容交界处的背景、边距，不能借全局样式修改意外改变消息表现。

## 2. 参考依据与还原方式

主要参考用户提供的 Muse 头像与活动页面，以及以下官方资料：

- [Muse 官方设计说明](https://muse.ai/blog/how-we-designed-muse)：解释头像、主会话、活动、权限与成果的产品设计。
- [Muse 官方 App Store 页面与截图](https://apps.apple.com/us/app/muse-from-meta/id6760173601)：观察实际聊天、顶栏、输入框、连接器和任务界面的视觉关系。
- [Muse 官方产品介绍视频](https://www.youtube.com/watch?v=wHn0hTjvFoo)：后续动态核对参考；本次未完成视频逐帧验证，不将下面的动画参数声称为 Muse 的原始参数。
- [Taste Skill](https://github.com/Leonxlnx/taste-skill)：辅助统一字体、边界、留白、图标、层级和克制的交互反馈。

官方静态图可确认白灰基底、居中头像、浅灰胶囊分栏、轻量图标与内容优先的层级。宣传图外围的彩色光晕不视为 App 内的背景设计。图片不能证明 Muse 具体采用了哪种原生模糊组件，也不能证明完整滚动行为。

本方案按用户明确的目标设计：聊天内容铺满屏幕，经过悬浮顶栏后方时呈现轻微模糊；顶栏不以不透明矩形挤占会话高度。此处是确定的目标效果，不冒充对 Muse 源码的判断。

Taste Skill 原文面向网站。本次采用其视觉系统与检查原则，不照搬营销首页结构、装饰性场景、桌面悬停或与原生 App 不适配的规则。下面的尺寸和动效是本项目的设计规格，不是对 Muse 的精确测量。

## 3. 信息架构

```text
连接服务器 / 创建或登录账号
                 │
          ┌──────┴──────┐
        聊天           我的
         │              │
  会话列表 / 新建       用户头像与账号
  当前会话              │
  文件系统快捷入口      ├─ 定时任务（默认）
  插件市场快捷入口      │   ├─ 待执行 / 已完成
  输入框与工具栏        │   └─ 任务详情 / 创建 / 编辑
                        ├─ 设置
                        │   ├─ 模型 / 网页搜索
                        │   ├─ 主动服务 / 语言
                        │   └─ 服务器 / 退出登录 / Stop Host
                        └─ 插件市场
                            ├─ 市场 / 已安装
                            └─ 详情 / 安装 / 启停 / 更新 / 授权
```

不新增第三个底部页面，不复制 Muse 的 Today 活动流，也不引入尚未实现的 Ideas、Goals、购物或全局活动日志。定时任务继续指当前 Host 的 Schedule，不将其改造成另一套任务系统。

聊天默认进入现有主会话，主会话标识、欢迎消息、不可删除规则和其他会话的创建规则保持现状。

## 4. 视觉系统

### 4.1 色彩与层级

先还原 Muse 参考图中的控件外观，再用 Taste Skill 校准留白、对比、字体与整体协调度。不为了增加配色而为每个控件设计彩色状态，也不要求每个交互都带描边、光圈、缩放或提示动画。

| 用途 | 初始设计值 / 规则 | 使用方式 |
| --- | --- | --- |
| 页面基底 | `#FFFFFF` | 聊天与主要页面，不再有紫青光晕 |
| 分组背景 | `#F6F6F7` | 设置背景、浅层次容器、弹层内部 |
| 控件轨道 | `#F1F2F3` | 分栏底座、次要控件 |
| 主文字 | `#17191C` | 标题、账号、正文标签 |
| 辅助文字 | `#73777E` | 描述、时间、说明；实测小字号可读性 |
| 细分隔线 | `#E9EAEC` | 必要的组内分隔，不给每层容器都加边框 |
| 主要操作 | `#1B1C1F` | 发送、保存等主操作 |
| 真实素材色彩 | 保留原色 | 蓝色鲸鱼、用户头像、插件图标、文件图标和图片 |
| 必要链接与状态色 | 沿用清晰、克制的语义色 | 链接、已有成功/失败状态、危险操作；不扩展为整个控件的彩色外框或整块彩底 |

这套界面的色彩丰富度主要来自真实头像、Logo、图片与内容，另以必要的语义色辅助。补充色只在真实需要的区域决定，不预先安排一整套装饰色再寻找使用位置。Muse 的具体控件还原优先于 Taste Skill 的一般配色建议。

**各区域的搭配：**

| 区域 | 搭配方式 |
| --- | --- |
| 聊天顶栏 | 半透明白底、黑灰图标；菜单展开通过轻灰底区分。Go Bot 鲸鱼保持原有蓝色 |
| 用户消息 | 白色系中的轻中性底，搭配深色文字；与无外层气泡的助手内容形成轻微区分，不改助手内部样式 |
| 输入框 | 保留原多行输入区和底部操作行，白色或极浅灰底、轻灰边界、深色发送按钮；聚焦保持原有外观，没有额外外圈、变色边框或发光 |
| 底部导航 | 参考第一张图：近白悬浮底座，选中入口后方为很浅的灰色圆润底片；图标为黑灰线框 |
| 我的三分栏 | 参考第二张图：浅灰轨道，选中项为白色胶囊与极轻阴影；选中图标近黑，未选中为中灰 |
| 我的用户区 | 用户头像保留原色，未设置个人头像时使用项目鲸鱼 Logo；不额外强配暖色背景 |
| 定时任务 | 主体白灰，时钟与字段图标用黑灰；现有状态需要时以小图标或短标签区分，不染整张卡片 |
| 设置 | 普通行、选中项和开关以黑灰层级统一，保存主按钮保持深色 |
| 插件市场 | 真实插件图标提供色彩，操作与选择使用黑灰控件；保留必要的链接与状态表达 |
| 弹层与提示 | 白色外层、浅灰内容组；错误或提醒用就近的清晰说明，不额外套彩色提示容器 |

错误、危险操作和运行状态的业务语义保持现状，不因换色新增没有数据支持的状态。错误文字可以使用克制的语义色，但不将输入框整圈标红，也不同时叠加多种视觉提醒。

透明与模糊用于确有层叠关系的顶栏等位置。任务条目、表单与文字区优先清晰，不把所有容器都做成玻璃。

### 4.1.1 参考图中的控件还原

两张 Muse 图分别校准两类控件：第一张的底部导航采用近白底座和浅灰选中区域，图标保持黑灰；第二张的个人页面分栏采用浅灰轨道和带极轻阴影的白色选中胶囊，选中图标近黑、其余中灰。两者分别对照还原，不统一替换成一套通用彩色选中样式。

输入框维持参考图里的轻薄白灰外观。触屏聚焦通过光标、键盘与实际输入表达，无需新增焦点装饰；外接键盘与辅助技术继续使用必要的平台焦点指示。新增截图用于校准外观，不据此新增语音通话或改写助手消息布局。

### 4.1.2 其他控件与语义状态的设计边界

参考图未明确展示的状态，由本项目补充设计，要求与现有白灰界面协调。导航、个人分栏和输入框的上述还原规则不受此补充覆盖。

| 情况 | 建议配色 | 使用范围 |
| --- | --- | --- |
| 其他列表或选择项未选中 | 白底或既有浅灰底，黑灰文字 | 保持普通阅读状态 |
| 其他列表或选择项选中 | `#ECEEEF` 浅灰底、深色勾选与文字 | 模型、权限、会话等现有选择；选择差异优先靠底色与勾选，不统一加彩色边框 |
| 失败、错误、危险操作 | `#A54343` 克制红色 | 错误说明、小图标、危险动作文字；不渲染整圈输入框或整张卡片 |
| 警告、需注意 | `#88601F` 低饱和琥珀色 | 确有警告时的短说明与小图标，不把普通等待或暂停都改成警告 |
| 成功、完成 | `#3E6A52` 柔和绿色 | 已有成功或完成状态的勾选、短标签；不为所有已启用项新增绿色标记 |
| 文字链接 | `#39658F` 柔和蓝色 | 确实可点击的说明链接，不用于导航或输入焦点 |

这些是初始状态色，实施时结合实际底色检查可读性并微调。普通状态不因本表而新增提示；一次操作只保留必要的就地反馈，不同时增加彩框、彩底、横幅和动画。已有功能和状态含义保持原样，本轮补充的是颜色与轻量视觉区分。

### 4.2 字体、尺寸与留白

- 使用系统字体：iOS 的系统拉丁字体与中文回退、Android 的系统字体与中文回退。不另引装饰字体。
- 外围 UI 正文约 16/24，辅助信息 13/18，分组标题 18/24；账号名 24/30，字重 500。尊重系统字体缩放。
- 页面左右以 20dp 为主。各页标题、分组和列表共用对齐线。
- 设置行高度约 56–60dp；容器上下内边距 14–18dp，避免压缩成密集表格。
- 分组圆角约 18–22dp，底部弹层约 28dp；不为每个小图标再套圆角方块。
- 触控区域至少 44dp。小图标的可见尺寸与实际命中区域分开。
- 延续现有 Lucide 线框图标，尺寸约 20–22dp、线宽 1.6–1.8；底部导航单独使用 24dp、2dp 描边的 Lucide MessageCircle 与 UserRound，图标近黑；分栏和正文维持较轻线宽。导航图标不填实心背景，选中底片与图标分开绘制。文件类型与插件继续使用真实图标资源。
- 不把上述 UI 字号覆盖到助手 Markdown 样式；消息内现有字体层级保留。

## 5. 聊天页

### 5.1 铺底内容与模糊顶栏

聊天页面分为内容层、悬浮顶栏、底部输入区域与导航，不再让顶栏作为不透明普通布局行把会话向下挤。

```text
┌─────────────────────────────┐
│ 系统状态栏                   │
│ 会话列表    Go Bot头像    菜单 │ ← 清晰的悬浮控件
│ ···背景内容经过这里时轻微模糊·· │ ← 只作用于顶栏背后的内容
│                             │
│ 用户消息 / 助手内容           │
│ 图片 / 文件 / 工具执行        │ ← 内容层延伸到顶栏下方
│                             │
│ 待处理交互 / 输入框           │
│         聊天    我的          │ ← 浮动双入口
└─────────────────────────────┘
```

- 左侧会话列表入口、中央 Go Bot 头像、右侧组合菜单保留。头像独立展示，不加外壳或圆形底；头像下方的名称/状态置于白色胶囊，轻阴影明确其边界。普通状态仅显示 Go Bot，不附加“正常”标签。
- 顶栏使用真实背景模糊，以多段透明度蒙版连续渐隐，不另叠偏白遮罩；避免白雾和突兀的下沿。只有其后方的消息被模糊，按钮、头像和菜单不被一起模糊，也不给整个会话降低透明度。
- 首屏内容保留必要的顶部阅读间距，第一条消息初始可读；向上滚动后内容可以经过顶栏背后。不能把「全屏」实现成第一条消息永久被遮住。
- 模糊区域之外的消息保持原始清晰度；无明显硬边、粗线、重阴影或整块白色头部。
- 整体内容层铺底不意味着取消系统安全区。状态栏、刘海、相机孔、手势区与触控区域仍正确避让。
- 实现时优先考虑当前 Expo SDK 对应的 `expo-blur`。Android 需要按官方方式配置背景目标；动态列表与模糊层顺序必须正确。性能不足的设备可退化为同色半透明效果，不能退化为厚重遮挡。依据：[Expo BlurView 文档](https://docs.expo.dev/versions/latest/sdk/blur-view/)。

### 5.1.1 顶栏 Logo 与运行状态

头像下方胶囊在当前会话发送、运行或播放未结束时显示“处理中 / Working”及一个中性灰黑呼吸点，结束后恢复 Go Bot。依据现有发送与会话运行/播放状态，不发明执行工具、等待回答等细分状态。两种文字在同一固定尺寸容器内以约 220ms 短淡入淡出和 3dp 位移切换，不改变顶栏布局；头像与胶囊整体保持既有轻浮动。切换到别的会话只显示那个会话的真实状态。系统减少动态效果时关闭呼吸、位移和装饰浮动，文字仍能区分状态。

### 5.2 输入框和底部导航

- 输入框采用白色或极浅灰底、细灰边与柔和圆角。发送按钮为小面积深色；无旧紫色外描边和强发光。
- 附件草稿继续位于文字输入区上方，按添加顺序横向排列，保留缩略图、文件名与移除。选择附件仍只加入草稿，随消息一起发送。
- 「+」、模型、权限、停止生成和发送的功能全部保留。按用户最新要求沿用改造前的多行文字输入区与底部操作行：「+」、模型、权限、停止与发送仍保持原布局、尺寸及交互。展开的工具栏也保留原有布局和圆角，仅协调白灰底色；这一部分不照搬 Muse 的单行输入条。
- 工具栏继续提供相册、本地图片区、本地文件区；统一为浅灰底上的清晰图标与名称。
- 底部导航仅「聊天」「我的」，宽约 148dp，采用近白轻浮底座、浅灰圆润选中底片、黑灰线框图标。仅显示图标，保留辅助功能名称；选中不变蓝，依靠底片与细微明暗区分；与「我的」浅灰轨道上的白色选中胶囊分别还原。
- 键盘出现时收起底部导航，输入框跟随键盘；键盘关闭后恢复。不能覆盖输入框、待回答入口或最后一行消息。
- 消息底部留白由实际输入区域与安全区高度决定，不写死大块空白。

### 5.3 保持现有消息与会话行为

- 用户消息保留气泡；助手没有外层气泡。用户气泡采用 Muse 参考图中的浅蓝色（#CCE4FC），发送中的临时气泡保持同色，不改变附件在前、文本在后的内容顺序。
- 助手头像行、生成提示、内容左对齐、文字播放、连续工具卡片、图片横排与边缘渐变、文件下载卡片均沿用。
- 排队消息、steer、删除排队消息、停止生成、askuserquestion、普通权限审批及 Plan 交互均保留。关闭展示弹层不等于提交回答或拒绝审批。
- 会话列表仍从左侧展开，保留主会话、其他会话、新建、归档、当前选择和加载更多。样式改为白底、轻灰选中行，不使用厚重卡片堆叠。
- 主会话欢迎消息与模型配置引导保留；创建或发送前缺少可用模型时，继续明确提示并提供前往模型设置的路径，不伪造默认模型。
- 初始 Host 插件准备提示保留真实状态、错误与重试，外观改为低干扰的单行提示；不编造安装百分比。
- 新会话空态、加载中、失败重试的视觉随新风格统一，现有空态到发送后布局的动态不退化。

## 6. 「我的」页面

### 6.1 页面骨架

```text
                   用户头像
                     编辑
                    账号名

        时钟 定时任务 | 设置 | 插件市场

        当前分栏的真实内容
        ……

                  聊天   我的
```

- 参考 Muse 的居中头像、名字、分栏与内容节奏。这里展示的是现有用户头像和账号，不改成可编辑的 Agent 人格。
- 头像约 96dp，右下角轻量编辑标记；默认使用项目鲸鱼 Logo，已有自定义头像优先。点击继续选择图库或相机，个人头像仍只在本地按账号保存。
- 不增加顶部大号「我的」或另一个 Go Bot Logo。名称下不伪造 Muse 的「Checking price」工作状态；本次没有新增全局工作状态数据的需求。
- 三分栏为「定时任务」「设置」「插件市场」，图标分别采用时钟、设置、拼图。底座浅灰，总高约 42dp，选中项白色，阴影极轻。按最新要求只显示图标，分别为时钟、设置、拼图；文字名称作为辅助功能标签，不显示在分栏中。
- 首次进入「我的」默认选中定时任务；本次连接内保留用户之后选择的分栏与各自滚动位置。显式跳转设置或插件时进入指定位置。
- 上滑时头像与名字自然滚出，三分栏吸顶在安全区下方，底色轻薄。不固定一个巨大的头像区压缩列表。
- 不复制 Muse 的 Today 活动标题或其活动流。任务列表继续保留真实时间信息；需要日期分组时可用明确日期，不增加一层名为 Today 的概念。

### 6.2 定时任务分栏

- 保留「待执行 / 已完成」两类，用轻量文字切换，不叠两个同等厚重的胶囊导航。
- 分栏内容标题行放「定时任务」与右侧创建加号；不将创建按钮放在头像旁。
- 任务行采用浅灰柔和背景或轻分隔：时钟/状态图标、任务标题、下一次运行时间与必要状态。行内不塞完整 Prompt、所有规则或投递历史。
- 已暂停归入待执行，真正结束才归入已完成，判断沿用当前数据；进行中的现有标识保留。
- 点击任务打开底部详情：标题、状态、Next run、规则与时区、投递目标、任务指令、已有工作目录信息、最近一次投递时间。使用与字段相符的线框图标、浅灰底和白色信息组，避免纯白上叠纯白看不清边界。
- 立即运行、暂停/恢复、编辑、删除、打开关联会话、清理已完成等当前操作全部保留，按钮可用性由既有状态决定。
- 创建和编辑保留当前所有时间规则、投递目标和工作目录字段，不简化底层 Schedule 机制，也不增加任务搜索。

### 6.3 设置分栏

使用两到三个自然分组，不把每行包装成独立大按钮：

| 分组 | 入口 | 说明 |
| --- | --- | --- |
| 助手设置 | 模型、网页搜索、主动服务 | 右侧摘要仅显示真实已保存状态，不显示密钥 |
| 应用设置 | 语言、服务器地址 | 中文/英文在设备本地保存，与账号无关；服务器查看能力保留 |
| 账号与运行 | 退出登录、Stop Host | 两者语义保持不同，停止 Host 需确认 |

- 模型仍支持多端点、每端点多个模型、默认项和现有协议下拉选择。表单布局统一为浅灰输入底、清晰标签、黑色主按钮与低对比度次操作。
- 网页搜索沿用已有供应商选择与凭证表单，不新增或隐藏当前可用供应商。
- 主动服务保持默认关闭、启用时检查模型配置；缺少模型时引导去模型设置。现有只在 Debug 显示的诊断内容保持原规则。
- 内置图片生成设置当前隐藏，继续隐藏；相关插件从插件市场使用。
- 退出登录与 Stop Host 放在下方独立组，危险色只用于后者。退出登录不停止 Host，不改变现有连接语义。

### 6.4 插件市场分栏

- 将现有插件市场嵌入此处，保留「市场 / 已安装」、刷新、图标、名称、description、真实安装/运行状态与全部管理能力。
- 列表保持移动端一列排列，真实插件图标加名称和简短描述，右侧轻量状态或操作。不重绘第三方 Logo，不把包名改成另一个营销名称。
- 插件详情作为「我的」内部子页面，延续白灰风格；返回回到插件列表及原滚动位置，不跳到聊天。
- 详情中的版本、说明、教程、安装/更新/卸载、启用/停用、授权、已有诊断或重启入口全部保留；信息可折叠，但功能不删。
- API Key、OAuth、文件或文本输入等认证步骤继续由现有插件数据驱动，不按某个插件写死专属认证页面，也不改变凭证存储。
- 离开页面不取消安装；重新进入显示真实操作进度。安装失败显示错误与重试，不用全局遮罩锁住聊天或其他页面。
- 聊天右上角仍保留插件市场快捷入口，但跳转到同一份市场与管理状态，不另建一套独立插件页面。

## 8. 弹层、返回与动效

### 8.1 弹层层级

- 会话列表为左侧抽屉；工具栏、模型、权限、任务详情、设置表单与认证输入采用底部弹层或现有子页面关系。
- 大弹层使用浅灰背景、白色分组、细弱边界和顶端短拖柄；不沿用紫色渐变。能否拖动关闭取决于实现与表单状态，不展示没有行为的拖动承诺。
- 点遮罩关闭最上层，弹层内部点击不穿透。Android 返回先收起最上层，再退出内部详情，最后才处理一级页面返回。
- 有未保存修改的表单继续确认放弃；单纯浏览不弹多余确认。
- 打开相机、图库、文件选择器或授权浏览器前，先完成当前需要关闭的弹层过渡，避免原生 Modal 叠加导致遮挡。
- 审批/提问弹层的关闭仍只是隐藏界面，不自动执行批准、拒绝或回答。

### 8.2 返回路径

| 场景 | 返回目的地 |
| --- | --- |
| 插件列表 → 插件详情 | 同一分栏原列表位置 |
| 插件详情 → 授权流程 | 插件详情；取消与授权失败按现有规则处理 |
| 聊天快捷入口 → 插件市场 | 显式返回可回到原聊天；详情返回先到市场，不越级 |
| 定时任务 → 任务详情 | 同一任务列表与分类 |
| 任务详情 → 打开会话 | 聊天中指定会话；保留任务页状态供再次进入 |
| 缺少模型 → 前往配置 | 我的/设置/模型；返回保留原聊天草稿 |
| 外部 OAuth → App | 原插件授权上下文，不丢失安装与配置状态 |

默认显示聊天。主动点击底部「我的」保留上次分栏；快捷入口的目的分栏优先。一级页面切换不隐式提交、清空或取消任何业务操作。

### 8.3 动效规格

| 交互 | 建议表现 |
| --- | --- |
| 聊天 / 我的切换 | 约 280ms，共用一个动画进度，旧页滑出与新页滑入相邻连续进行；底部选中底片同步移动，快速反向切换从当前位置继续，不重置到起点 |
| 我的三分栏切换 | 选中底片约 180–220ms 滑动，内容短淡入；不做整页大幅滑动 |
| 底部弹层 | 约 240ms 上滑，约 180ms 收回；遮罩同步变化 |
| 点击行或图标 | 轻微明暗变化或平台原生按压反馈；不统一追加缩放、弹跳或阴影动画 |
| 头像区域滚出 | 随自然滚动离场，分栏吸顶，不突然跳切 |
| 聊天顶栏 | 内容从后方经过时自然模糊；不周期性闪烁、不模糊前景按钮 |

不绑定整页左右滑手势来抢占消息图片、表格与代码内部的横滑。动效只影响呈现，不延迟请求或成为业务状态。系统开启减少动态效果时，取消位移和装饰循环，保留短淡入与状态反馈。已有助手执行动态不在此表中重写。

### 8.4 元素状态规范

选中、按下、焦点、禁用、处理中含义不同，但不要求每种状态都额外设计一层视觉装饰。按下采用轻微反馈，选中按参考图表达；触屏输入聚焦无需改变输入框外观。处理中来自真实请求，不能等动画播完才开始请求。

| 元素 | 默认 / 未选中 | 选中 / 展开 | 按下与过渡 |
| --- | --- | --- | --- |
| 底部聊天、我的 | 近白悬浮底座，黑灰线框图标，不显示文字 | 极浅灰圆润底片，近黑图标，保留辅助功能名称；辅助技术标记选中，不使用蓝色 | 选中底片随切换移动，按下仅局部浅灰反馈；重复点当前项不重播页面入场 |
| 我的三分栏 | 浅灰轨道，中灰图标，不显示文字，无独立边框 | 白色胶囊、极轻阴影、近黑图标，不使用蓝色 | 底片轻滑，内容短淡入；标题与轨道高度不变 |
| 待执行、已完成 | 辅助色文字 | 深色文字、略高字重，短细深灰线标记当前分类 | 约 160–180ms 切换文字与标记，不再叠一层厚胶囊 |
| 会话列表行 | 白底，深色标题、灰色摘要 | 轻灰底，保留主会话标识；不加重阴影 | 按下灰色略加深，不缩放整行，不推动其他条目 |
| 模型、权限及表单单选项 | 白色或浅灰底，深灰标签 | 浅灰底、深色勾选或单选标记，同时保留完整名称 | 按下立即反馈；需要请求确认的选择按真实结果显示，失败提示且不假报已生效 |
| 输入框 | 轻灰边界、白色或极浅灰底 | 触屏聚焦后外观保持一致，显示光标与键盘；无额外描边、外圈或光效 | 键盘与输入区域自然衔接，边界不变色、不加粗，错误用就近文字说明 |
| 顶栏及工具栏图标按钮 | 无彩色实心底，深灰线框 | 对应菜单展开时使用浅灰底，图标仍为黑灰 | 按下只做短暂轻灰明暗反馈，松开恢复；不额外缩放 |
| 主按钮 | 深色底、白字 | 非选择控件，没有持续“选中”态 | 按下略调深浅，尺寸不变；禁用与处理中见下文 |
| 次按钮、文字操作 | 中性浅底或文字，沿用一种次级样式 | 非选择控件不强造选中态 | 按下局部底色加深；链接保留可识别的蓝色 |
| 开关 | 浅灰轨道、白色圆点 | 深灰轨道、白色圆点 | 圆点约 180ms 平滑移动；模型检查或保存期间阻止重复提交，失败恢复真实状态并解释原因 |
| 本地图片、文件多选 | 真实缩略图或文件图标，无全屏彩色遮罩 | 细深灰边、清晰勾选；图像只可有极轻遮罩 | 勾选短淡入，保持网格与行尺寸；保留原有多选模式和动作 |
| 插件、任务等可点击条目 | 白灰界面、真实图标与描述 | 详情入口不假设为多选项；已有启用/完成状态独立展示 | 按下浅灰反馈，进入详情使用统一页面或弹层过渡 |
| Host 文件树目录 | 深灰文件夹图标、名称与方向标 | 展开标记转向、子级自然缩进；不把展开误画成文件选中 | 方向标短旋转；新增行清晰出现，不逐条播放长入场动画 |

底部导航与分栏的选中底片只表达当前页面，不发光、不持续呼吸。任务的完成、插件的启用、某行被按下与某项被选中分别表达，不能共用一个绿色圆点造成歧义。

### 8.5 操作反馈、加载与错误

| 情况 | 表现与规则 |
| --- | --- |
| 不可操作 | 控件采用浅灰底与低强调标签，保留可读性和禁用语义；模型缺失等需要引导的情况不能仅灰掉入口，仍通过现有校验提示解决路径 |
| 点击后请求尚未结束 | 当前按钮原位置显示小型进度指示和简短动词，如“保存中”“停止中”；宽度保持稳定，当前动作不可重复提交，其他无关区域仍可操作 |
| 插件安装 / 更新 | 对应插件显示真实安装状态和进度指示，可离开页面继续聊天；不显示整页阻塞遮罩，不编造百分比 |
| 首次拉取列表 | 在列表内容区显示简洁的加载指示与必要说明，页面标题、分栏和返回仍可用；不制造整屏闪光骨架 |
| 刷新已有内容 | 原内容保留，使用局部刷新反馈；成功后更新变化，不清空列表再全量入场 |
| 保存成功 | 当前表单保存动作出现短暂勾选或“已保存”，约 1.5–2 秒后恢复；以实际成功返回为准，不同时叠加横幅、弹窗和 Toast |
| 表单错误 | 字段附近显示明确、简短的文字说明，输入值保留；不新增红色描边、警告底板或抖动动画 |
| 请求失败 | 在发生操作的位置显示可读原因与重试。若确实需要全局提醒，只显示一份简短提示，不覆盖主要内容 |
| 删除、Stop Host | 延续现有确认流程，明确动作对象；执行中反馈和失败原因留在相关界面。关闭确认框不执行动作 |
| 空列表 | 简单线框图标、一句说明；有现有创建或导入能力时提供对应操作。已完成任务为空不显示错误样式 |
| 连接中断与重连 | 根据已有连接状态展示轻量文字提示；不因页面切换虚构断线，不新增频繁全屏警告 |

顶栏 Logo 状态只观察已有发送、会话运行和文字播放状态。本次不改变助手消息的等待、生成、工具执行、队列与审批状态机，也不对其复制按钮、图片滑动、文本播放重复添加另一套动态。上述反馈用于外围控件与管理页面，已有业务结果仍是状态依据。

### 8.6 连贯性与可访问性

- 所有按钮触下后立即有反馈，最终成功或失败再依据请求结果呈现；视觉按压不能代替成功确认。
- 同类控件共用轻量反馈和动效曲线；没有必要的状态装饰直接省略，不为每个控件都追加动效。
- 切换内容前后保留容器边界与已保存的滚动位置，不为显示选中态增加边框厚度、改变字号或挤动相邻元素。
- 颜色外还提供名称、勾选、开关位置或文字状态；选中、展开、禁用与处理中为辅助技术提供相应语义。
- 不给每次点击强加震动或声音。本轮不为触觉反馈新增依赖；系统选择器沿用原生反馈。
- 减少动态效果时状态仍明确；不靠滑动底片或位移动画作为唯一的选中提示。

## 9. 实现位置与状态保护

以下为本轮改造的模块边界，业务逻辑与消息渲染保持原有职责。

- `mobile/App.tsx`：双入口导航、按页面处理安全区与覆盖层、保留共享连接和缓存；不再依赖旧三页的数字位置跳转。

- `mobile/src/ui.tsx`：中性视觉 token 与弹层外观；明确样式影响边界，不能直接把消息正文的现有 token 全量替换。
- 消息渲染、Markdown、媒体分组、SSE、会话缓存、插件操作管理与后端保持既有实现。组件拆分只为承载新布局，不重写这些业务。

切换「聊天 / 我的」、三个分栏或打开详情，必须保留当前会话、草稿附件、滚动位置、文本播放状态、待处理交互和插件操作。不得因页面重新挂载而重建 Host 连接、重复加载全量历史、取消安装或中断正在生成的轮次。生命周期订阅沿用现有规则，不让隐藏页面重复订阅。
