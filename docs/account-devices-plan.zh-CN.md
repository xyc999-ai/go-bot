# 同账号客户端与移动端设备分栏

## 2026-11-27 确认的行为

移动端设备页显示同一账号下的手机、平板和桌面电脑。Web 不上报设备身份、不登记在线状态，也不产生设备租约；聊天事件流、消息同步和重连保持原样。设备页没有左滑删除、手动删除或远程退出功能，保留已断开的原生设备历史。

手机和平板使用 `expo-device` 的 `modelName`，例如 iPhone 13 mini。无法取得机型时退回 iPhone、iPad 或 Android。桌面端显示系统电脑名称，不添加 Go Bot 前缀：macOS 优先读取 `scutil --get ComputerName`，Windows/Linux 使用系统 hostname；名称不可读时退回系统通用名称。系统读取在 Electron 主进程完成，macOS 查询有超时限制，不让渲染进程访问任意系统命令。电脑名称在桌面客户端启动时读取，改名后重启客户端生效。

客户端不再生成或保存随机安装 ID，不使用 IDFV、序列号、UDID 或 MAC 地址。旧手机 `client-identity.txt` 不再读取或更新；桌面配置中的旧 `clientId` 在启动时移除，其他偏好不变。

## 身份分组与当前设备

原生客户端在现有 SSE 请求头 `X-Go-Bot-Client` 中上报：

```json
{"type":"mobile","platform":"ios","model":"iPhone 13 mini"}
```

桌面端上报 `desktop`、运行平台和系统电脑名称，名称沿用协议字段 `model`。平台最长 32 字节，名称最长 120 个 Unicode 字符，不接受控制字符。

Controller 按当前账号内的 `(type, platform, model)` 合并记录，设备名称先去除首尾空白。Redis 记录键及公开的 `id` 是服务端根据这些字段生成的确定性哈希，不是客户端生成的安装标识，也不是认证凭证。移动端按这些字段匹配「此设备」，不依赖公开 `id`。

这是按名称分组：两台同型号 iPhone 在同账号内合并显示，只要其中一条连接有效就显示在线。两台同名同平台电脑也会合并；电脑改名则产生新记录。不用硬件标识尝试推断是否为同一台物理设备。

## 连接与 Redis

Controller 只在上游成功返回 HTTP 200 `text/event-stream` 后登记原生设备。元信息在 Controller 消费，不转发给 Host 或模型；一次失败请求不产生在线记录。

仍使用账号 Hash `user:<userid>` 的 `clients` 字段（JSON），不增加独立 Redis 设备键，也不在 Controller 内存维护权威设备表。每个设备分组保存类型、平台、名称、最近在线时间，以及 `connectionId → expiresAt` 的连接租约表；时间使用 Unix 毫秒。

每条成功 SSE 由 Controller 分配独立临时连接 UUID，每 30 秒续期，租期 90 秒。结束一条连接只释放自己的租约，不能影响同一名称下的其他连接或重连。正常断开立即移除租约；异常退出后，在租约过期时被视为断开。历史设备保留，最多 50 条；达到上限时淘汰最久未在线的已断开记录。

通过 Redis WATCH/事务更新 `clients`，避免并发覆盖和影响账号模型、插件等字段。接口读取不启动 Host，不读取会话内容，也不返回内部连接 UUID 或租约表。

## 兼容旧版本

- 旧 Web 客户端继续正常聊天；即使发送旧身份请求头，Controller 也不登记或续期。
- 设备列表读取或在线记录更新时，事务清除已有 Web 记录。
- 已有明确名称的原生安装记录按新规则合并，保留全部独立连接租约和最大的最近在线时间。
- 旧 iPhone 记录只有随机 ID、没有具体机型，保留为历史记录，不猜测与新机型的对应关系。旧桌面通用名称去掉 Go Bot 前缀显示。
- 旧原生客户端可以继续发送安装 ID；有名称时按名称分组，没有名称时暂时沿用旧 ID。更新后的客户端不发送安装 ID。
- 先升级 Controller，再安装新原生客户端。旧 Controller 要求安装 ID，无法接受新客户端只含类型、平台和名称的请求头，会返回 HTTP 400。

## 设备页

`GET /v1/clients` 使用现有 `X-User-ID`，返回原生设备的 `id`、`type`、`platform`、`model`、`status` 和 `lastSeenAt`。列表在线优先，再按最近在线时间排序。

设备页保留「此设备」和「其他设备」分组、现有图标与列表样式。只有可见且应用处于前台时，每 5 秒请求 Controller 刷新；也支持手动刷新。页面只在内存保存本次响应，历史来自 Redis，不在客户端另外持久化。为兼容未升级的 Controller，移动端也过滤旧响应里的 Web 条目。

状态表示应用事件流是否连接，不表示设备是否开机。静默失联按 90 秒租约判断，不承诺瞬时检测。读取失败保留已显示内容并允许重试。

## 验证范围

- 同名原生设备合并、名称/平台/客户端类型隔离，以及按名称识别「此设备」。
- 多条连接、关闭一条、旧连接晚于重连结束、租约过期和正常断开。
- 上游握手失败不登记；Web 仍收到聊天事件但不产生在线记录。
- Redis 并发更新、旧 Web 清理、旧原生历史保留、跨 Controller 可见及其他账号字段写入不覆盖设备信息。
- 桌面原生名称读取、Unicode 名称和回退路径，无随机 ID 持久化；Web 实际浏览器请求不带设备信息。
- 三端类型检查、Web/Desktop 构建与原生 Electron 冒烟验证；新增 Expo 模块的 iOS Pod 和 Release 构建检查。
