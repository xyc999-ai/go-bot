# Web 与移动端流式文本连续展示方案

状态：已实现并完成 Web、Android 模拟器验收。范围只涉及客户端展示；Host、Controller、SSE 协议、会话日志、AgentLoop 和 500ms 的正式事件检查均保持原样。

## 1. 目标

将收到的完整文本和已经展示到的位置分开管理。每条增量只追加接收内容，播放位置继续向前，不按 text-delta 重启动画。Web 与 React Native 复用同一套播放算法；不添加打字光标。接受 Markdown 在语法闭合时发生的局部排版变化，不增加表格或代码块的专用缓存解析器。

## 2. 数据与身份

- 原始 TranscriptCache 继续即时接收、去重并保存完整 SSE 数据，播放不阻塞网络接收、业务状态和日志游标。
- 客户端消息保留公开事件已有的 turn、step 元数据；草稿与正式消息通过同一 turn/step 和文本块序号对应。
- 每个可见会话有一个临时播放器，保存各文本块的目标文本、Unicode 字符边界和展示位置，不持久化到后端、本地文件或账号设置。
- 正式 assistant/message 替换草稿时，使用稳定展示标识并保留已显示位置；目标文本补全后继续展示剩余内容。若发生重试或修正，保留实际相同的已展示前缀，不拼接已经废弃的回答。

## 3. 连续播放

- 通过 requestAnimationFrame 驱动，最多约 30 次/秒更新文本，不为每个字单独创建动画或定时器。
- 以 Unicode 字符簇为边界，支持中文、代理对和组合 emoji；运行环境缺少 Intl.Segmenter 时退化为 Unicode 码点，至少不截断代理对。
- 基础速度每秒 60 个字符簇，按积压量自适应提速，最高每秒 360 个字符簇。不是要求用户等完整真实生成时间，也不人为延迟首段内容到达。
- 先展示更早的文本，再推进后续文本；正文之后的工具、图片和文件保持原有内容块顺序。它们自身没有逐字动画，执行状态及审批/提问仍由原始数据立即更新。
- 后端完成不等于客户端播放完成。完成事件不跳过待展示文字；生成提示可在客户端播放结束后消失，但停止操作、排队、模型切换和发送逻辑仍以真实后端状态为准。
- Markdown 仍交给两端现有库，以当前已展示前缀重新解析。无变化的文本组件记忆化，避免每一帧重复解析所有历史文本。

## 4. 生命周期

| 情况 | 行为 |
| --- | --- |
| 首次加载历史、加载更早消息 | 已有文本直接显示，不重播历史 |
| 当前可见会话收到新内容 | 连续渐进展示 |
| 正式消息提交、turn/end 到达 | 保留位置，继续展示剩余文本 |
| 切换会话或账号 | 丢弃旧会话播放器；新会话当前快照直接显示 |
| SSE 重连 baseline | 直接显示恢复快照，后续增量恢复渐进展示 |
| 页面隐藏、移动端进入后台 | 停止动画；回来后直接显示已收到的内容 |
| 用户启用系统减少动态效果 | 直接显示全部已收到文字 |
| 取消、失败、重试、草稿消失 | 以真实 Transcript 为准，移除不存在的草稿；不将未提交内容伪造成正式消息 |
| 审批、askuserquestion | 不等待文字播放，继续通过原有面板即时交互 |

## 5. 实现位置

- `frontend/src/chat/textPlayback.ts`：不依赖 UI 的播放器，负责身份映射、接收/展示状态、速率和有序输出。
- `frontend/src/chat/useTextPlayback.ts`：共用 React hook，负责帧调度和清理。
- `frontend/src/chat/transcript.ts`：保留 step，记录重连 baseline 的客户端重置计数，不改变对外协议。
- Web Chat 与 mobile Conversation：在内容分组和渲染之前使用播放器；分别接入页面可见性和 AppState/减少动态效果。
- 两端现有 Markdown 组件：保留渲染规则，增加稳定文本的组件记忆化。

## 6. 验收

1. 共享逻辑测试：增量追加不重置、完整消息与 turn/end 不跳满、分块/分 step 顺序、用户消息不延迟、历史不重播、重连/换会话、取消/重试、Unicode、减少动态效果和调度清理。
2. Web 类型检查、已有测试和构建；移动端类型检查和 Android QA 构建。
3. 使用固定长 Markdown 的模拟模型服务，不消耗真实模型 tokens。通过真实 Host→Controller→Web/Android 链路验证慢速、快速和大段分片输入。
4. 录制真实页面和模拟器画面，检查等待、连续播放、后端完成但仍播放、最终完整内容及重新进入会话不重播。

## 7. 实测结果（2026-11-22）

- Web 测试共 36 项通过，包括追加增量、正式消息提交、turn/end、跨文本块、跨 step、取消/修正、历史分页、baseline、Unicode 和速度控制。
- Web 生产构建、移动端 TypeScript 检查通过；最终 Android QA Release 包编译、覆盖安装成功。没有新增第三方依赖。
- 固定 843 字符 Markdown 分成 169 次增量，在约 0.11 秒到达。真实 Web 和 Android 页面均继续渐进展示，Web 采样约 4 秒完成展开；正式消息到达没有跳过剩余文字。
- 额外验证了慢速增量、Web 停止、切换会话后历史直接展示，以及真实 Go shellexecute 工具调用前后的正文与工具卡片衔接；工具场景始终只有一个助手头像。
- 下一 step 的开始帧可能先于上一 step 的日志投影，客户端只在同一 turn 确实有后续流式草稿时暂留前一步草稿，待对应日志到达继续使用同一播放位置；不是新增会话事实。
- 使用本机模拟模型服务，没有消耗真实模型 tokens。验证通过真实 Host→Controller→客户端链路，未更改后端事件机制。iOS 本次未做独立运行验收。
- 私有录制、日志和测试脚本位于被忽略的 `.local/playback-qa/`，不作为开源仓库资源提交。

## 8. 边界

不更改权限审批、工具管线、会话事实和后端完成语义；不增加新模型协议、第三方渲染库、光标或用户配置项。播放速度为前端常量，可根据验收体验调整。没有保证每秒 360 个字符簇足以瞬间消化任意长度的回复；系统减少动态效果、后台恢复和重连均可直接追上当前内容。
