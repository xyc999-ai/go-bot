# Markdown 展示与演示更新方案

## 范围

Web 保留已有文字、引用和表格视觉风格。表格和代码块增加固定在容器上方的轻量复制操作，内容在容器内部横向滚动，页面本身不横向溢出。表格允许长单元格在合理列宽内换行，列数多时滚动；代码保留换行和缩进，不强行折行。

表格与代码块均复制对应元素的原始 Markdown，保留表格分隔符、围栏与语言标记；不转成 TSV，也不复制渲染后的纯文本。操作提供成功或失败反馈，中英文标签随本地语言切换。Web 同时支持安全上下文 Clipboard API 和普通 HTTP 的用户点击复制。

移动端参考 Taste Skill 的对齐、留白、层级和克制交互，沿用现有近白底与浅青紫环境色。正文 16px/27px 行高；段落、标题、列表与引用保留更清楚的垂直间距。行内代码采用中性浅灰底和等宽字体，代码块采用浅灰底、细边框、语言名与始终可见的复制入口。表格采用中性表头，固定同列宽度，内部横向滚动。复制按钮至少 44px 触控区域，滚动与会话纵向滚动互不替代。

除用户附件顺序调整外，不更改 Host、AgentLoop、SSE 或日志内容，不引入语法高亮库；保持已有 Markdown 图片按原文显示的约定。

## 实施与验证

提取双端各自的 Markdown 展示组件。验证短表格、多列表格、长代码、复制后的实际内容、流式追加后复制最新内容、中英文、Web 深浅主题以及移动端纵横滚动。通过真实 Web 和原生 Android 应用截图检查，先验证排版再录制。

## 演示素材

使用已保存的原始真实会话日志、公开投影和原始交付产物重新展示，不再次调用付费模型，不改写原始请求或回答。重录中英文移动端各五个案例：浏览器调研、Word、PPT、双参考图生图、定时任务；同时完成中英文 Web 生图演示。全程展示完整会话页面；Word/PPT 成品继续使用原有 WPS 实际展示截图，与会话片段组成同一动图，中文版 PPT 重点为第二页。

导出 GIF 使用每帧独立调色板，核对解码后的关键帧与截图，避免额外压暗或丢失主体细节。更新两份 README 的资源引用和必要说明，保持每组案例第一行三个、第二行两个居中。原始录制与验证脚本留在被忽略的 .local 中。

## 用户附件顺序

草稿保留现有附件预览。发送时 Host 按上传顺序组装 image/file，再追加本次 text；模型上下文与新会话日志一致。双端用户气泡将附件置顶，旧历史仅在显示时调整顺序，不改写事实；助手的文字、工具、图片和文件仍按原顺序穿插。
